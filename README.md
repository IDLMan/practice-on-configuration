# Эмулятор UNIX-подобной оболочки — вариант № 21

Практическая работа № 1 по дисциплине «Конфигурационное управление».
РТУ МИРЭА. Реализованы все 5 этапов на **Python 3.10+**.
Приложение использует только стандартную библиотеку Python.

## Общее описание

Консольное приложение эмулирует небольшой набор команд UNIX.
При запуске загружает виртуальную файловую систему (VFS) из CSV
в оперативную память. Вся работа с ней, включая копирование,
проходит исключительно в памяти — исходные CSV не изменяются.

В REPL приглашение строится из действительных данных ОС:
`username@hostname:~$ `. Можно задать собственное через `--prompt`.
Парсер разделяет строку **по пробелам**, как требует вариант 21;
обработка кавычек намеренно не реализуется.

## Структура проекта

```text
src/                  # исходный код эмулятора
  main.py             # точка входа и запуск
  shell.py            # REPL и команды
  config.py           # аргументы CLI и JSON
  scripting.py        # запуск стартовых сценариев

tests/                # автоматические тесты unittest

examples/             # сценарии команд и скрипты настоящей ОС
.gitignore            # исключает служебные и сгенерированные файлы
run.sh / run.bat      # скрипты запуска для Linux/macOS и Windows
README.md             # описание и руководство
```

## Запуск

Из корня проекта на Linux/macOS:

```bash
./run.sh
./run.sh --vfs data/nested.csv --script examples/demo_copy.txt
./run.sh --config examples/config.json
```

На Windows:

```bat
run.bat
run.bat --config examples/config.json
```

Универсально (если Python доступен в PATH):

```bash
python -m src.main
python -m src.main --help
```

При `--script` исполняется сценарий, затем программа завершается.
Без `--script` запускается интерактивный REPL. Сборка не требуется.
Для тестов:

```bash
python -m unittest discover -s tests -v
```

## Этап 1 — REPL

Интерфейс CLI, приглашение по реальным данным ОС, простой парсер.
В первоначальном прототипе `ls` и `cd` — заглушки, которые печатают
свои имена и аргументы. Команда `exit` завершает REPL. Для неверной
команды или `exit` с параметрами выводится сообщение об ошибке.
Рабочий прототип представлен в отдельном снимке первого этапа.

## Этап 2 — настройки и стартовые скрипты

| Опция | Назначение |
| --- | --- |
| `--vfs PATH` | Путь к CSV-источнику виртуальных файлов |
| `--prompt TEXT` | Пользовательское приглашение к вводу |
| `--script PATH` | Текстовый сценарий команд эмулятора |
| `--config PATH` | Путь к файлу настроек JSON |

JSON допускает строковые поля `vfs`, `prompt`, `script`:

```json
{
  "vfs": "../data/nested.csv",
  "prompt": "my-shell$ ",
  "script": "startup.txt"
}
```

Пути в JSON отсчитываются от местоположения конфигурационного файла.
Пути, переданные через CLI, — от текущего рабочего каталога.
**CLI имеет приоритет над JSON**. При запуске печатаются все настройки.
Если `--vfs` отсутствует и не задан в JSON, используется образ
`data/nested.csv` из каталога проекта.

Скрипты поддерживают комментарии `#` (отдельные строки и комментарии
после команды). Приложение отображает команды и их результаты как
диалог, продолжает после ошибки, печатает её номер строки и возвращает
код 1, если были ошибки. `exit` прерывает сценарий.

## Этап 3 — формат и загрузка VFS

CSV-таблица содержит три столбца:

- `path` — абсолютный канонический POSIX-путь (`/docs/readme.txt`);
- `kind` — `dir` (директория) или `file` (файл);
- `content_base64` — содержимое файла, закодированное в Base64.

Директории указываются отдельно (включая промежуточные) и не имеют
содержимого. `/` добавляется автоматически. Пример вложенной иерархии:
`/docs` → `/docs/tutorial` → `/docs/tutorial/lesson.txt`.
Используется словарь Python `dict[str, Entry]`; содержимое файлов
представляется в `bytes`. Все операции выполняются с этими данными.

Для демонстрации есть три VFS: `data/minimal.csv` (только `/`),
`data/files.csv` (несколько файлов) и `data/nested.csv` (три уровня
и бинарный файл). При ошибках чтения, путей или base64 печатается
сообщение; пользовательские данные на физическом диске не меняются.

## Этап 4 — основные команды

| Команда | Назначение и аргументы |
| --- | --- |
| `ls [PATH]` | Отобразить дочерние имена или указанный файл |
| `cd [PATH]` | Изменить текущий каталог; без параметров — корень `/` |
| `pwd` | Вывести текущий абсолютный каталог |
| `tac FILE [FILE...]` | Вывести строки UTF-8 файлов в обратном порядке |
| `exit` | Завершить работу оболочки |

`ls` без аргументов выводит текущий каталог. Поддерживаются
относительные пути, `.` и `..`, а также абсолютные POSIX-пути.
`pwd` не принимает аргументов. `tac` принимает как минимум один файл.
Для несуществующих путей, неподходящих типов и неправильных аргументов
команды выдают диагностические сообщения.

## Этап 5 — дополнительная команда

`cp SOURCE DEST` — побайтовое копирование обычного файла **в памяти**.
Если `DEST` — каталог, копия получает имя исходного файла.
Если `DEST` — файл, его содержимое заменяется. Родительский каталог
назначения должен существовать. Копирование каталогов не поддерживается,
как и копирование файла в самого себя. Нельзя перезаписать
существующий каталог файлом. Поддерживаются бинарные файлы.
Изменения доступны сразу для `ls`, `tac`, `cp`, но исходный CSV не меняется.

## Пример работы

```text
user@host:~$ pwd
/
user@host:~$ ls /docs
readme.txt
tutorial
user@host:~$ cp /notes.txt /docs
user@host:~$ ls /docs
notes.txt
readme.txt
tutorial
user@host:~$ tac /docs/readme.txt
line three
line two
line one
user@host:~$ cd /docs
user@host:~$ pwd
/docs
user@host:~$ exit
```
