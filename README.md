# Эмулятор командной оболочки UNIX — вариант 21

Практическая работа № 1, этапы 1–4. Python 3.10+, без зависимостей.

## Запуск и тестирование

```bash
./run.sh
./run.sh --script examples/demo_commands.txt
./run.sh --config examples/config.json
python3 -m unittest discover -s tests -v
./examples/run_commands.sh
./examples/run_vfs_minimal.sh
./examples/run_vfs_files.sh
./examples/run_vfs_nested.sh
./examples/run_vfs_error.sh
```

Windows: `run.bat`; эквивалентный запуск `python -m src.main`.
Скрипты ОС для этапа 2 — `examples/run_defaults.sh`,
`examples/run_custom_prompt.sh`, `examples/run_from_config.sh`.

## Этап 1: REPL

Консольное приглашение `username@hostname:~$ ` собирается из имени
пользователя и машины реальной ОС. Парсер разбивает строку по пробелам,
без интерпретации кавычек (как требуется вариантом 21).
Команда `exit` завершает оболочку; неизвестные команды вызывают ошибку.
Заглушки `ls` и `cd` представлены в снимке первого этапа проекта.

## Этап 2: конфигурация и стартовые сценарии

- `--vfs PATH` — источник VFS.
- `--prompt TEXT` — собственное приглашение REPL.
- `--script PATH` — стартовый сценарий команд.
- `--config PATH` — конфигурация JSON.

Пример файла `examples/config.json` содержит ключи `vfs`, `prompt`,
`script`. Настройки CLI имеют приоритет перед JSON. Пути из JSON
отсчитываются от папки конфигурации; CLI — от текущего каталога.
При запуске приложение выводит все активные параметры.

В сценариях доступны комментарии `#`. Вывод эмулирует интерактивный
диалог; ошибки сопровождаются номерами строк и кодом завершения 1.
Скрипт исполняется полностью до `exit` (ошибки не останавливают его).

## Этап 3: VFS из CSV

Все файлы представлены структурой `dict` и байтами в оперативной
памяти. Исходный CSV читается один раз, затем не изменяется.
Распаковка на физический диск или выполнение команд ОС отсутствуют.
По умолчанию загружается `data/nested.csv`.

Заголовок CSV: `path,kind,content_base64`. Здесь `path` — абсолютный
канонический POSIX-путь, `kind` — `dir`/`file`, а `content_base64` —
содержимое файла в base64. Каталоги записываются явно, включая
промежуточные уровни; корень `/` создаётся автоматически.

Образы: `data/minimal.csv` (только корень), `data/files.csv` (2 файла),
`data/nested.csv` (вложенные каталоги и бинарный файл).
Неправильные пути, base64, структура или отсутствие файла приводят
к диагностике ошибки.

## Этап 4: основные команды

| Команда | Поведение |
| --- | --- |
| `ls [path]` | Имена внутри каталога или имя отдельного файла |
| `cd [path]` | Смена текущего каталога; без аргументов — `/` |
| `pwd` | Полный абсолютный путь текущего каталога |
| `tac FILE [FILE...]` | Строки каждого UTF-8 файла в обратном порядке |
| `exit` | Выход из оболочки |

При ошибках (лишние аргументы, отсутствующий путь, файл вместо
каталога, недопустимый UTF-8) выводится сообщение без аварийного
завершения REPL. `tac` сохраняет границы строк.

Демонстрация всех команд: `examples/demo_commands.txt`.
Демонстрация ошибок: `examples/demo_errors.txt`.
После проверки тестов зафиксировать четвёртый этап отдельным коммитом.

Сценарий `examples/run_vfs_command_errors.sh` также проверяет
ошибки команд при загруженной VFS.
